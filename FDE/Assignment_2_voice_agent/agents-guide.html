How to use this page

Open a topic, read the workshop-level guidance, and mark it complete. The authoritative contributor reference remains AGENTS.md.

The core path is cascaded: caller speech becomes text, the LLM calls reservation tools, and the reply becomes speech. Each stage is visible and replaceable for workshop learning.

  • pipeline/agent.py owns guardrails and tools.
  • providers.py adapts mock, OpenAI, and Groq.
  • voice_loop.py runs typed or microphone turns and reports timing.
  • smoke_test.py is the offline regression check.

mocks/ demonstrates SIP and IVR behavior without a carrier. livekit/ is a separate optional local WebRTC room demo.

Mock mode runs the real agent and tool flow with no key, network, SDK, or paid call. The smoke test should end with RESULT: PASS.

cd pipeline && python3 smoke_test.py

Use typed turns first; they remove microphone and audio-device uncertainty while exercising the complete reasoning path.

cd pipeline && PROVIDER=mock python3 voice_loop.py --text

Aurora handles availability, reservations, room options, changes or cancellations, transfer, and ending a call. It redirects unrelated requests such as weather, news, coding, medical, legal, and financial questions.

Availability, prices, confirmation numbers, policies, and guest details must come from trusted tools or data—never from a made-up reply. Check availability before offering rooms; book only after room selection, contact details, and an explicit confirmation. Transfer ambiguous, risky, unsupported, or human-requested work.

Voice replies stay to one or two plain spoken sentences: no Markdown, bullets, or emoji.

PROVIDER=mock is the no-cost rehearsal and fallback. Live OpenAI needs OPENAI_API_KEY; Groq needs GROQ_API_KEY. Copy pipeline/config.example.env to pipeline/.env only for local live work, and never commit or print credentials.

Use TTS_BACKEND=system to keep a live-LLM rehearsal local and cost-aware. Provider TTS can sound more polished but adds network dependency and usage cost; disclose it for a demo or pull request.

cd pipeline && cp config.example.env .env

Microphone mode records 16 kHz PCM and uses WebRTC VAD. ENDPOINT_SILENCE_MS=600 ends a caller turn after a pause; VAD_AGGRESSIVENESS runs from 0 to 3. Shorter pauses feel faster but can interrupt speech, while longer pauses are more forgiving but add latency.

Keep --text usable: it is the dependable fallback for a missing microphone, unavailable audio libraries, noisy rooms, or provider diagnosis. The displayed STT, LLM/tools, and TTS timings are workshop evidence, not a production guarantee.

LiveKit is an optional local room/session step after typed and microphone modes. A caller and agent become room participants, audio becomes a track, and the browser can show transcript and agent state.

The room demo does not provision a phone number, a carrier connection, or SIP by itself. The SIP mock only prints representative call flow and simulated REFER transfer. Real telephony needs a SIP trunk, dispatch/routing, an agent worker, audio bridging, authentication, observability, and operational safeguards.

cd mocks && python3 demo_call.py --transfer

Agent, guardrail, tool, or call-control changes need an updated smoke assertion and a passing offline test. Test typed mode before authorized live provider work. SIP or IVR changes need the relevant mock demo.

For livekit/web/, start the local demo and manually check the browser at desktop and mobile widths, including keyboard use. For this standalone guide, check links, whitespace, inline JavaScript syntax, expand/collapse controls, copy feedback, and reduced-motion behavior.

Use four-space Python indentation and conventional names: snake_case, PascalCase, and UPPER_SNAKE_CASE. Prefer small explicit functions, keep provider code in providers.py, avoid unrelated formatting, and add dependencies only when the capability requires them.

Commit subjects should be short, imperative, and behavior-focused. Pull requests explain the user-visible change and validation, link the assignment or issue when relevant, and include screenshots for browser UI changes. Call out new configuration, external services, credential needs, cost, and remaining risk.
